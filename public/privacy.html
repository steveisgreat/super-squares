This policy explains what [PRODUCT NAME], operated by [COMPANY], collects and does today, and what is planned. It describes how the software actually works. The sections marked for review cover features that are not live yet.

1. What we store

  • Game data. When a host creates a game, we store its settings (team names, scoring mode, dates), the grid, and the names the host types onto squares and into the player list. We also store a "paid / unpaid" flag per player that the host sets for their own tracking, plus scores and winners.
  • Nothing else about players. Players do not create accounts, and we do not ask players for or store their email addresses, phone numbers or payment details. Names are whatever the host chooses to type, so hosts should use first names or nicknames.
  • Server logs. Our hosting provider processes ordinary request information (such as IP address and browser type) to deliver and secure the site.

2. Where it is stored

The site is hosted on Vercel, and game data (and, once email sign-in is live, host account data) is kept in a Postgres database run by Neon. These providers process data for us. [HOSTING REGIONS — confirm.]

3. Cookies and device storage

  • Host session cookie (sbs_host). When a host signs in, we set this cookie so they stay signed in for up to 30 days. It is HttpOnly, so page scripts cannot read it, and it holds a signed expiry value, not personal data. People who only view boards do not get it. Email sign-in, once live, replaces it with the cookie described in section 9.
  • Player view memory (browser localStorage). On a board's player page, your browser remembers which name you picked from the list so it is preselected next time. It stays on your device, is not sent to us, and you can clear it in your browser settings.
  • Scorer phone cookie (sbs_scorer). When a host hands score entry to a phone, that phone gets a cookie for that one board. It lasts up to 24 hours, is HttpOnly, and holds a random value, not personal data. The host can end it at any time. The browser also keeps a note (localStorage) that this phone was a scorer for that board.
  • We do not use advertising or tracking cookies.

4. Third parties

  • Google Fonts. The app loads fonts from Google (fonts.googleapis.com and fonts.gstatic.com), so your browser sends Google your IP address and standard request details. [Consider self-hosting fonts — for review.]
  • Team logos. Team and league logos load from ESPN's image server (a.espncdn.com), so your browser sends ESPN your IP address and standard request details.
  • Live scores. Score lookups are made by our server, not your browser, so your device does not contact the score provider. Only public game and team information is requested; no player names are sent.
  • Hosting providers. Vercel and Neon, as above.
  • We do not sell personal information, show ads or run analytics today.

5. Who can see a board

Anyone who has a board's link (for example from its QR code) can view it, including every name and the paid / unpaid flags on it. The link is not a password. Hosts should share it only with people they are happy to have see those names, and should not type sensitive information onto a board. Managing games requires the host to sign in.

  • Pending sign-in (browser localStorage, sbs-login-pending). While a host waits for a code, their browser will keep the email address they typed, a request number and an expiry time, so that an app closed in the meantime reopens at the code step. It is not used after 15 minutes and is removed when sign-in finishes or is dismissed, or the next time the sign-in form opens. It never holds the code or the link.
